# Future hypotheses queue

**Created:** 2026-08-20

Questions this project has identified as worth testing but has **not** authorised, together with what
each is blocked on. A line here is a **placeholder, not an approval**: nothing in this file may be
tested until it has its own pre-registration frozen before its data exists.

**Status vocabulary**

- `queued-pending-infrastructure` — the question is testable in principle, but a required data artifact
  does not exist at adequate quality.
- `queued-pending-forward-data` — the question cannot be tested on any existing data because the
  relevant population is saturated; it needs observations accumulated after a pre-registration.
- `queued-pending-both` — both apply.

## Queue

### 1. 1-hop network attention spillover

**Question.** Do high-GST earnings announcements produce different next-day abnormal volume (or
return) at directly-linked firms than low-GST announcements?

**Status:** `queued-pending-both`

**Blocked by.** Ruled BLOCKED on 2026-08-20 —
`External_Scrutiny_Audit_2026-08-20/NETWORK_SPILLOVER_PILOT_RULING_2026-08-20.md`. The existing
relationship artifact is 42 hand-specified `EXPLORATORY_STATIC` edges over 3 anchors, not an
SEC-derived network. The event panel is 63 rows. The comparison has already been run and published as
`NO_DAILY_NETWORK_SPILLOVER` with a **2-event** high-GST cell, AMD has no GST coverage at all, and
2 of 3 anchors plus 14 of 63 events overlap the saturated 152-event population.

**Unblocking requires (both).** A reproducible relationship network with per-edge provenance from a
documented source, replacing the static edge list; **and** forward anchor events accumulated after a
pre-registration, with GST coverage verified per anchor at enrolment.

### 2. GST/Wikipedia attention-divergence regime

**Question.** Do GST-high / Wikipedia-low events differ from GST-high / Wikipedia-high events?

**Status:** `queued-pending-forward-data`

**Blocked by.** The historical split lives entirely inside the exhausted 152-event population.
Descriptive characterisation was permitted on 2026-08-20 —
`External_Scrutiny_Audit_2026-08-20/SATURATED_DATA_DESCRIPTIVE_CENSUS_RULING_2026-08-20.md` — but
**any comparison of the two groups' market outcomes on that data is prohibited absolutely.**

**Census facts a forward design must handle**
(`External_Scrutiny_Audit_2026-08-20/WIKIPEDIA_DIVERGENCE_CENSUS_2026-08-20.md`): 45/152 = 29.6% have
`wiki_zscore < 0`; the divergent set sits nearer the selection floor (`gst_z` median 6.689 vs 8.391),
so divergence is **not independent of the selection variable**; and 13 tickers carry all 45 divergent
events with MSFT alone at 17.8%.

**Unblocking requires.** Phase 2 panel observations accumulated after a forward pre-registration's own
commit timestamp, with GST magnitude controlled, matched or stratified, plus firm-clustered inference
and a per-ticker concentration cap. A draft pre-registration exists and is **held uncommitted**
pending review.

### 3. Wikipedia pageviews as an independent predictor

**Question.** Do Wikipedia pageviews predict anything in their own right, rather than as a GST proxy?

**Status:** `queued-pending-forward-data`

**Blocked by.** `Live Signal Engine/Wikipedia_Pageviews_IndependenceCheck_Note.md` established the two
series are only weakly related (Pearson r = 0.2442, p = 0.0024; ~6% shared variance) and concluded a
pre-registered test "would be a reasonable next step, **if pursued**". No pre-registration was created
and none exists. The 152-event population is saturated.

**Unblocking requires.** A pre-registration frozen before forward data exists. Note the same selection
constraint as item 2: every event in the historical population satisfies `gst_zscore >= 5` by
construction, so that data cannot supply a low-GST contrast group.

### 4. Regime dependence of the earnings-surprise association

**Question.** Is the surprise/reaction association regime-dependent? The 2010–2017 replication helped
in 5 of 8 years and 4 of 9 firms, with the annual pattern strong early, absent mid-period, strong
again at the end.

**Status:** `queued-pending-forward-data`

**Blocked by.** *Signal Without Strategy* §10 records this explicitly as a hypothesis **generated by**
the observed instability: "We record this as a hypothesis *generated by* the observed instability. We
did not test it, it is not established, and testing it retrospectively on the same data would be
exactly the multiple-testing error this program is trying to avoid."

**Unblocking requires.** A non-overlapping sample or forward data, with regimes defined before
outcomes are opened.

### 5. H16 incremental explanatory power for realized volatility

**Question.** Does GST add incremental explanatory power for realized volatility beyond implied
volatility?

**Status:** `queued-pending-forward-data`

**Blocked by.** `Live Signal Engine/H16_Exploratory_PreRegistration.md` is explicit that the
152-event population "is fully saturated by every prior test in this project" and that any promising
result "requires a fresh, independently-pre-registered confirmatory test on new forward data before
being treated as real." The 2026-07-26 run (commit `4e2ed62`) returned incremental R² +0.0753,
GST coefficient +0.3968, t = 3.337, p = 0.0011, n = 125 — **exploratory only**.

**Additional constraint identified 2026-08-20.** The reconciliation
(`External_Scrutiny_Audit_2026-08-20/GST_INCREMENTAL_VALUE_RECONCILIATION_2026-08-20.md`) established
that H16's `fixed_window_zscore` takes its numerator from the anchor week's own GST value, and that
the 4-day outcome window lies **entirely inside** that week for all 125 events. Any forward version
must use a **strictly pre-event** attention feature, or it will again measure contemporaneous
association rather than prediction.

2. Nothing here may be tested on the 152-event population, the semiconductor outcome populations, or

3. Each item requires its own pre-registration, frozen before its data exists.
4. Removing an item requires a dated note recording why.
5. Adding an item requires naming what it is blocked on, in the same form as the entries above.
